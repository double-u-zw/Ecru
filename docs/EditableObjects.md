# 图形填充与图片批注（Ecru Dev build 18）

分支：`codex/editable-images-shape-fill`。沿用 build 17 的 Google Ink、真实压力、六工具、页面 overlay 和安全保存架构；未改写笔迹算法。正式 Ecru、Beta 2 安装包与历史发布均保留。

## 使用

- 选择或圈选已有图形，点“边框 / 线宽 / 填充”。填充面板明确区分无填充、跟随当前图形边框、自定义颜色，并提供现有常用色、柔和色、最近色、原生自定义色与实时不透明度滑块。
- 修改已选图形不会修改新图形默认值。“对象 → 将当前图形样式设为默认”是显式操作；“对象 → 恢复手绘”保留 build 17 的原轨迹恢复。
- PDF 获得输入焦点时，⌘V 插入剪贴板图片；也可用“编辑 → 插入图片”、页面右键“粘贴图片”、Finder 或截图缩略图拖入。支持原生文件承诺接收器，不读取剪贴板网络 URL。
- 普通粘贴位于当前页可见区域中央；右键与拖放用对应 PDF 坐标。初始图片按比例适配可见区域。插入自动进入选择状态，拖动移动，角点等比例缩放。
- 选择状态的“图片”菜单包含裁剪、重置裁剪、旋转 90°、位置锁定、前后层级、复制剪切、组合和取消组合。裁剪时在图片上拖出保留区域，点“确认裁剪”；Esc 取消此次裁剪。剪切与删除、移动与缩放都进入现有撤销系统。
- 插入后点“完成”、Esc 或点击空白区域，恢复此前工具。若此前是笔，笔色、宽度和真实压力设置都保留；完成点击不会落下额外笔迹。
- 笔和自由荧光笔直接写在图片上；橡皮只作用于 Ecru 笔迹。只有选择 / 圈选编辑图片。锁定的图片以及包含它的组合不能拖动或缩放，仍可在上方书写。
- 图片与笔迹默认独立。圈选、Shift 多选后在对象菜单组合，后续选择任一成员会选择整组。组合可移动、等比例缩放、旋转或取消；正文关联标记也可圈选。

## 存储与兼容

`AnnotationStore` 增加可选图片对象、按 SHA-256 去重的不可变图像数据、组合和绘制次序；旧 JSON 缺少这些字段仍能读取。每个图片只保存源资产引用、页号、PDF 页坐标矩形、旋转、归一化裁剪区域和锁定状态。图片并非临时视图；页面 overlay 只是模型的显示适配器。

PDF 导出使用标准 Stamp 批注的 appearance stream：图片资源与透明蒙版嵌入 PDF，页面原文仍可搜索。私有文档 manifest 包含继续编辑所需源图片和几何。采用原来的 qpdf 对象保留、安全校验与原子替换流程；不光栅化整页，也不依赖原截图或缓存文件。外部移除图片时不会擅自恢复；外部移动或改变标准图片几何、版本不支持或模型校验失败时受限只读。

新图片在所有已有 Ecru 笔迹和图片下方；后续书写在上方。显式前后层级在页面 renderer 和导出时采用同一顺序。Ecru 文字高亮 / 区域标记保持原有标准 PDF 适配器，位于图片 / 笔迹层之下，正文批注继续用原有锚点和 Text 批注。外部阅读器自行修改排列或 appearance 的能力不由 Ecru 保证。

新增模式或图片 / 组合 / 排列的最低 reader 为 5，草稿恢复格式为 7；旧笔迹、reader 1–4、恢复 1–6 仍可读。历史图形没有 fillMode 时按原 RGBA 保持实际外观，视作自定义填充；不根据颜色相同猜测跟随意图。已有跟随笔色 / 20% 绘图偏好仍读取原设置。旧 Ecru 应保护 reader 5 文件为只读；升级不清除开发版偏好或用户草稿。

## 质量与边界

输入由 ImageIO 读取主图并应用 EXIF 方向；保持完整像素尺寸，转换一次为 8-bit SDR sRGB 无损 PNG，保留 alpha。宽色域经颜色管理映射至 sRGB；HDR 使用 ImageIO 的 SDR 主图表示，不保留 HDR 增益图或超出 SDR 的亮度。这不是 HDR 编辑器。移动、裁剪、旋转和重复保存不重新编码源资产；标准 PDF 图片资源也经独立检查为完整像素、Flate 无损压缩和透明 SMask。

上限：输入 96 MiB、4000 万像素、单边 32768 像素、归一化 PNG 24 MiB；沿用整个批注 manifest 64 MiB 上限，超限明确拒绝插入并保持现有内容。解码 / 颜色转换在后台运行，显示使用按实际屏幕像素分档的缩略缓存，缓存预算 192 MiB；显示缩略图不替换源图片或 PDF 导出资源。

当前旋转入口为 90° 步进；裁剪是矩形、比例缩放始终保留当前图片比例。一次文件拖入 / 文件对话框处理一张图片。跨软件复制单张图片提供原图 PNG；Ecru 内复制使用私有对象剪贴板，保留裁剪、旋转、组关系和源数据，正文内容仍使用原有文本复制方式。

实现接口参考：[ImageIO 主图读取](https://developer.apple.com/documentation/imageio/cgimagesource)、[PDFKit appearance stream](https://developer.apple.com/documentation/pdfkit/pdfannotation/hasappearancestream)。

## 验证与真人验收

- `Scripts/test-image-objects.sh`：78 项，图片 / 填充、后台剪贴板插入、多选、移动缩放裁剪旋转、组合与锁定、撤销、两轮保存重开、草稿和只读限制；页面四个旋转角度与 0.5/1/2/4 倍缩放；PNG/JPEG/TIFF/HEIC/16 位输入。另以 pypdf / Pillow 独立检查标准 appearance：完整像素、源 RGB 误差为 0、alpha 一致、原文仍可提取。
- `Scripts/test-complex-pdf.sh`：普通 / 旋转 / 表单 / 附件文档加入实际图片后保存、恢复和再保存；签名、密码、权限、XFA、脚本及组合复杂文件拒绝图片编辑并保持原字节。
- `Scripts/test-writing-ui.sh`：33 项（含原有 21 项）；新增真实 AppKit responder 链的搜索和 Markdown 文本粘贴、PDF 图片粘贴、820 / 1200 pt 窗口布局、Esc 裁剪与工具恢复，恢复原剪贴板。所有试验使用隔离数据目录和合成 PDF。
- `Scripts/test-image-performance.sh`：15 MP 图片源保留全尺寸，12 张图片页面连续绘制 40 帧的合成基准；显示缓存和完整源分别验证。它不代表真实滚动或 Pencil 延迟。
- 已用 macOS 预览实际打开合成保存文档，核对嵌入图片、小字、透明叠层、图片上方笔迹及独立图形填充；原始图片文件已由测试删除。
- Universal 2 分别编译 arm64 / x86_64，并核对相同构建身份、资源与签名。Intel 路径在 Apple Silicon 的 Rosetta 上执行图片、书写和输入生命周期回归；实际 Intel 设备尚需人工验收。

真人请用开发版检查：系统区域截图复制后 ⌘V；截图缩略图直接拖入；角点与裁剪手感；图片上 Pencil 书写 / 倾斜橡皮；圈选组合后移动 / 取消组合；完成后回笔；保存后在预览和 Ecru 重开再次编辑。真实 HDR 截图、超大复杂文档长时间手写、实际 Intel 硬件仍须人工验收。
