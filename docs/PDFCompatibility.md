# 复杂 PDF 兼容性（开发分支，尚未发布）

公开稳定基线仍为 v0.5.0-beta.2。本说明对应 `codex/complex-pdf-compatibility` 的 Ecru Dev；不描述历史安装包的新能力。

## 日常使用

| 文档实际条件 | 可用功能 | 保存保护 |
| --- | --- | --- |
| 普通、可可靠解析的 PDF | 阅读、搜索、导航、缩放及全部 Ecru 批注工具 | 原子保存、另存、撤销重做和恢复 |
| 普通 AcroForm、Widget；未带签名、XFA、活动行为或权限限制 | 对原页面添加 Ecru 批注；原字段值和外观继续显示 | 打开时先做对象保留预检；保留字段树、Widget、外观流及共享引用；不提供填表或改变字段值 |
| EmbeddedFiles、FileAttachment、关联附件 `/AF` | 主体页面阅读和 Ecru 批注 | 保留原附件数据、文件规格及名称树/页面/关联文件引用；预检失败只读；暂无附件管理器 |
| 密码保护或其他加密 PDF | 原生安全输入框解锁、重试和取消；成功后只读阅读及搜索 | 当前所有加密文档只读，即使权限允许批注也不提供加密写回；不导出解密副本 |
| 数字签名字段、签名字典、ByteRange，或认证/使用权限 `/Perms` | 静态阅读和搜索 | 签名仅检测，未验证有效性；签名原件不能保存或另存批注副本；修改可能令签名失效 |
| XFA、活动动作、JavaScript、RichMedia、Movie/Sound/Screen/3D、Portfolio | 在内存中禁用动作后阅读主体静态页 | 不执行脚本、启动程序、远程跳转、提交表单或媒体行为；原文件只读；不支持动态 XFA 执行和 Portfolio 包内浏览 |
| 解析警告或对象保留预检失败 | 有可靠静态页时只读 | 不自动修复并覆盖；禁止副本转换和恢复覆盖 |
| 无法解密、不完整结构、没有可用页面或无效页框 | 拒绝打开并显示原因 | 原件保留 |

多个特征叠加时执行更严格的保护。普通文档没有兼容性弹窗；只读文档默认使用选择工具，原生窗口显示只读状态。点击状态图标或尝试保存可查看具体限制。

打开密码仅授权解密阅读，与批注权限不同。密码只用于当次解锁，不写入日志、设置、钥匙串或恢复记录。解密后的静态阅读数据仅存在进程内存中；原始加密字节仍为会话的原件。当前实现不承诺清零进程内所有密码临时内存。

## 静态批注副本

XFA、活动内容或 Portfolio 文档，在不存在加密、签名、认证、解析异常且权限允许批注与打印时，状态面板提供“创建静态批注副本”。用户需先确认转换损失，再选择一个**不存在的新文件名**。不覆盖原件或已有文件。

副本保存当前 PDFKit 可显示的页面、绘制及可选择文字。动态表单行为、附件、脚本、媒体、Portfolio、原有可编辑批注模型和其他原对象图不保留；原批注可见外观成为页面内容。副本不能恢复未呈现的动态 XFA 内容。签名文件不开放此入口，避免把失去签名保护的页面当成有效签名副本。

副本生成后，落盘前逐页检查页框、旋转、原文字字符是否保留，并比较静态页面渲染；还检查没有残余表单、附件、签名或活动结构及注释。校验失败则不创建文件。渲染比较有抗锯齿容差，是转换保护而非对任意动态 PDF 的完整语义证明。新副本明确标为“静态批注副本”，可以添加 Ecru 批注、保存和重新打开。

## 保存工程约束

PDFKit 负责页面呈现、搜索和新批注外观。QPDF 负责严格对象解析、特征检测、内存阅读视图及对象图保存。

保存以原始 PDF 的对象图为底，仅替换已确认属于 Ecru 的页面批注槽位并添加当前管理的批注；保留其他原注释、页面绘制、资源、目录、字段树、附件、元数据和目录扩展。QPDF 仍然是完整重写器，**没有实现字节增量更新，也不能维持原密码学签名**，因此签名与加密写回被禁止。历史 Ecru 数据键和清单格式保持兼容。

QPDF 返回导出前，及后台原子替换前，比较原件和重开产物的原对象图：间接引用建立双向映射，验证共享关系和循环，比较字典、数组、原始流字节及流字典。仅允许管理批注、交叉引用信息、流长度表示与文件 ID 等必要变化。再运行原有的页面文字、页框、旋转、目录、绘图/图像资源、批注、清单和透明度校验。重开成功本身不是安全保存的依据。

手写修改继续使用原值类型模型和异步恢复；普通文档的原子写入、外部文件冲突、另存目标占用和保存期间新修改保护保持。只读文档不启动恢复写入，也不自动清理原路径已有草稿；旧草稿不能绕过当前文档保护。只读的正常关闭允许保留该草稿。

对象遍历与验证有深度/工作量上限；超过上限会拒绝解析或禁止导出。解析异常优先保护；例如 PDFKit 外部替换图像页面后产生零偏移孤立对象时，可能只能只读。

## 可重复测试

需要 Xcode Command Line Tools、CMake、Python 3 和 `Tests/requirements.txt`，并需 OpenSSL 生成一次性的自签名签名测试样本：

```sh
zsh Scripts/build.sh
zsh Scripts/test.sh
zsh Scripts/test-complex-pdf.sh
zsh Scripts/build-universal.sh
```

可用 `ECRU_TEST_PYTHON=/path/to/python3` 指定测试 Python。合成文档和每次隔离的输出/恢复记录都位于 `.build/complex-pdf/`，不提交用户资料。签名样本的私钥在临时目录生成并删除；OpenSSL 仅核验测试样本的 CMS 和覆盖字节，不建立证书信任；Ecru 不提供签名验证。

语料包括普通、旋转/裁剪、AES-256/RC4 密码、空打开密码但限制权限、真实自签名签名、普通表单、表单和附件叠加、XFA、EmbeddedFiles/FileAttachment/AF、直接动作字典、RichMedia、Portfolio、混合特征、损坏与截断文件；另有故意篡改字段/附件及包含文字 `/ByteRange` 的无签名对照。

核心测试覆盖搜索、渲染、只读事务、拒绝保存/另存、权限不绕过、撤销重做、恢复、原件字节不变、连续保存/关闭重开、副本转换及保存、图关系校验拒绝损坏。独立 pypdf 检查字段值、Widget 外观和附件字节/引用。隐藏原生窗口检查只读默认工具、禁用编辑、状态、导航和关闭。可显式运行 `ECRU_PASSWORD_DIALOG_TEST=1 .build/test-binaries/ComplexPDFWindowTests` 验证实际密码对话框；此命令会短暂显示窗口并测试取消和错误密码重试，请勿与其他前台 UI runner 同时运行。原有存储、批注、输入及笔迹回归继续执行。

## 本次验证结果（2026-10-12）

- 209 项复杂文档核心检查、32 项独立 pypdf 结构检查、52 项隐藏原生窗口/限制对话框检查通过；另有 6 项真实原生密码对话框的取消、安全输入和错误重试检查通过。
- 原有回归中的 142 项存储/冲突/恢复、43 项批注、128 项笔迹及 44 项输入生命周期检查通过；笔刷和 Google Ink 回归也继续执行。
- Universal 2 开发构建通过，包含 arm64 和 x86_64，最低部署版本 macOS 13；同一复杂测试套件在 x86_64 / Rosetta 下也通过，未更新已安装的 Ecru 或 Ecru Dev。
- 前台窗口通过 101 项阅读/手写/保存、5 项隔离进程重开、3 项阅读位置和 61 项文字批注/公式/长文档检查，以及 5 项引擎切换隔离检查。旧展示样本生成器会写出零偏移孤立对象，测试仅对隔离生成的样本归一化；应用对用户 PDF 的异常只读规则保持。
- 本机原始 PDFKit 探针：测试样本的静态页面和文字可读取；未批注直接导出时，普通表单、附件、XFA 与活动结构在该组简单样本中可以保留对象图。但加密样本（含禁止批注权限的样本）直接导出均变成未加密 PDF。签名导出虽保留签名字典和引用，独立 OpenSSL 校验确认重写后的覆盖字节已失效。这是不能让直接 PDFKit 导出承担安全保存的实际证据。
- 这些结果限定于合成样本与本机 PDFKit；不推断其他 macOS 版本或所有第三方 PDF 生成器具有相同行为。`PDFKitCapabilityProbe.swift` 随复杂测试脚本重复运行，输出位于 `.build/complex-pdf/pdfkit-probe.txt`。

### 2026-10-12 安装版窗口复验及修复

安装版 `ab5e099` 的前台验收完成了普通文档的搜索、翻页、缩放、笔迹/自由荧光笔/文字高亮/文字批注、撤销重做、保存和重开；密码取消、错误重试及 AES/RC4 解锁只读；权限限制和签名未验证提示；表单与附件的批注、原路径保存、另存及二次保存。三份实际窗口保存结果通过原对象图及可编辑模型重开校验，另用 pypdf 核对字段值、附件字节和关联。

该轮验收发现 `ab5e099` 创建静态副本时可能崩溃：`PDFPage.copy()` 仍关联原文档，设置旋转触发正在显示或隐藏的 `PDFThumbnailView` 更新。原核心与隐藏窗口测试没有覆盖这个页面通知路径。修复改用从禁用活动内容的字节独立解析的绘制文档，不改变阅读窗口绑定的页对象。新增带真实缩略图视图的旋转/XFA/混合文档回归，验证原页面无通知、旋转和文件字节不变、副本可编辑重开。新回归在修复前触发 AppKit 索引异常，修复后通过。

修复候选通过 209 项核心、32 项独立结构、64 项原生窗口检查。隔离前台窗口也完成旋转/裁剪静态副本的损失说明、创建、批注保存、关闭重开、搜索和第二页显示；独立检查副本的文字、页框、旋转和活动结构移除。损坏样本显示“无法安全打开此 PDF”。崩溃后原生恢复提示已确认，但窗口自动化在重启后失去可靠输入连接，恢复内容到再次保存的完整前台流程尚未确认；自动化核心恢复测试通过。

全部验收使用合成文档或其副本。44 份受保护样本与整理基线一致，58 份此次隔离原件字节不变；正式与安装版 Dev 的 App 包字节均保持不变。恢复目录保留，不加入样本 ZIP 或仓库。

安装版仍为 `ab5e099`，不能把修复候选的静态副本验收结果归于该安装版。修复构建单独保存在 `.build/apps/`；没有更新正式应用、发布 Release 或更改历史安装包。

本次本机环境为 macOS 27.0.1；以 macOS 13 为部署目标构建两种架构。部署目标和 Rosetta 测试不等于已在 macOS 13 或真实 Intel 设备验收。
